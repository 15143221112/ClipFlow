# 架构说明 Architecture

## 总体数据流

```
博主主页链接 / 单条作品链接
        │
        ▼
┌─ app.py (FastAPI) ───────────────────────────────────────┐
│  POST /api/task              → worker.run_pipeline       │
│  POST /api/download_single   → worker.process_single     │
│  GET  /api/tasks /videos /export /settings               │
└────────────────────────────┬─────────────────────────────┘
                             │
┌─ worker.py ────────────────▼─────────────────────────────┐
│ 采集全部作品(f2) → 入库(source=batch)                      │
│ 单条：下载 mp4 → ffmpeg 提取 mp3 → ASR 转写 → LLM 纠错     │
│      → 写飞书(upsert) → 更新库                             │
└────────────┬─────────────┬──────────────┬───────────────┘
             │             │              │
     ┌───────▼────┐ ┌──────▼─────┐ ┌──────▼───────┐
     │ SQLite     │ │ ASR 服务    │ │ LLM 纠错      │
     │ videos表   │ │ whisper    │ │ qwen-max/本地  │
     │ settings表 │ │ 讯飞/飞书   │ │ vLLM          │
     └────────────┘ └────────────┘ └──────────────┘
```

## 存储

- **videos 表**：作品全链路记录（源链接、来源类型、状态、本地视频/音频路径与 URL、逐字稿、时长、发布时间、时间戳）。
- **settings 表**：所有配置（点分 key → JSON value），页面「设置」写入即生效；首启自动从 settings.json 迁移。

## 关键设计

1. **先入库再下载**：批量先采集全部作品链接入库，cookie 失效后仍可基于库内链接重跑，数据不丢。
2. **upsert 写飞书**：按 aweme_id 判断，存在则更新记录、不存在则新建，保证重跑后飞书文本是最新正确版。
3. **转写可降级**：LLM 纠错失败保留 whisper 原文，不阻塞整条流水线。
4. **本地媒体可访问**：`/data` 静态挂载，local_url/audio_url 即下载/播放链接。
